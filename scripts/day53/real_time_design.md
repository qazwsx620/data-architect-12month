# Day53：Kafka/Flink 概念对比表 + 实时数仓架构设计

## 1. Kafka vs Flink 对比表

| 维度 | Kafka | Flink |
|------|-------|-------|
| 定位 | 消息中间件（传输） | 流计算引擎（计算） |
| 角色 | 存转发消息 | 实时处理计算 |
| 核心概念 | Topic/Partition/Producer/Consumer/Consumer Group | 流/窗口/事件时间/状态 |
| 典型用法 | 数据接入、解耦、削峰 | 实时聚合、实时报表 |

## 2. 离线 vs 实时架构对比图

```
【离线数仓】（Day47-52 已落地）
业务库 → ODS → DWD → DWS → ADS → 日报表（T+1，每天凌晨跑，看昨天）

【实时数仓】（概念版）
业务库/日志 → Kafka（消息接入）→ Flink（实时清洗/聚合）→ 实时DWS/ADS → 实时大屏（秒级，看当下）
```

| 维度 | 离线数仓 | 实时数仓 |
|------|----------|----------|
| 数据接入 | 批量抽取（T+1） | Kafka 消息（秒级） |
| 计算引擎 | Hive/Spark | Flink |
| 延迟 | 分钟~小时 | 秒级 |
| 报表 | 日报/月报 | 实时大屏/看板 |
| 场景 | 经营分析、报表 | 风控、实时监控 |

## 3. 实时订单数仓设计（纸面）

```
订单业务 → Kafka order_topic（按订单ID哈希选分区，同单保序）
                ↓ 消费
          Flink 实时任务
                ↓ 清洗（status映射）+ 窗口聚合（5分钟/小时）
          实时DWS（用户/商品实时汇总）
                ↓
          实时ADS → 实时大屏（GMV/订单量/客单价，秒级）
```

关键点：
- Topic：order_topic
- 清洗逻辑：复用离线 Day48 的枚举映射（status→可读）
- 窗口：滚动窗口（5分钟）算 GMV
- 事件时间：晚到订单按真实下单时间归窗
- 指标：实时 GMV / 订单量 / 客单价，秒级延迟
