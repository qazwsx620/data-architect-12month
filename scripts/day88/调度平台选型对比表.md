# Day88 实操：调度平台选型对比表

> 场景：订单数仓四层 ETL（ODS→DWD→DWS→ADS）+ 报表导出 + 质量校验，Python + MySQL，未来接 Spark/Flink

## 完整对比表

| 维度 | Airflow | DolphinScheduler | xxl-job | DataWorks |
|---|---|---|---|---|
| 一句话定位 | DAG即代码，数据工程事实标准 | 可视化DAG拖拽，工作流调度 | 轻量分布式定时任务中心 | 云原生数仓一站式调度 |
| DAG 定义方式 | DAG即代码（Python，可版本化/CI 测试） | DAG可视化拖拽（DSL 可导出） | 表达不了 DAG 依赖（子任务/分片是简单扩展） | 周期实例 + 依赖配置（含跨周期依赖） |
| 技术栈/生态 | python/Apache，Spark/dbt/Kafka 集成最全 | java/Apache，中文社区 | java 单体，轻量易部署 | 阿里云商业化云服务，绑定 MaxCompute/Hologres/EMR |
| 依赖编排 | 强（任意依赖/并行/动态生成） | 强（UI 连线） | 弱（定时触发 + 简单子任务） | 强（同周期/跨周期依赖） |
| 多租户/权限 | 弱（单租户为主） | 强（多租户） | 简单分组/执行器权限，偏弱 | 强（项目空间权限体系） |
| 运维成本 | 高（scheduler/webserver/worker/metadata DB + Python 环境自管） | 中（部署集中，Java 栈团队熟） | 低（单体轻量） | 低（云托管，按量付费） |
| 适合场景 | python、任务复杂、代码版本化 | java、可视化门槛低、多租户 | 单点定时任务（报表推送/定时清理） | 公司接入阿里云，不想管基础设施 |

## 订单数仓场景结论：Airflow

理由链（选型四步法）：
1. 依赖复杂度：四层依赖链，需要 DAG 编排 → 排除 xxl-job
2. 团队技术栈：Python → Airflow 优先于 DolphinScheduler
3. 部署形态：自建/混合云 → 排除 DataWorks（云托管）
4. 运维资源：有平台团队可维护 → 可承受 Airflow 组件复杂度
