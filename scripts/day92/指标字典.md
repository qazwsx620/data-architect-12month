# Day92 实操产出：订单数仓指标字典（v1.0）

> 用途：指标平台「定义层」的唯一权威源，BI / API / 报表全部引用此字典，禁止各自写 SQL。
> 版本：v1.0 ｜ 维护人：数据组 ｜ 生效日期：2026-11-06

## 一、指标字典总表

| 指标 | 英文名 | 类型 | 业务含义 | 计算公式（口径） | 时间口径 | 排除规则 | 数据源 | 负责人 |
|---|---|---|---|---|---|---|---|---|
| GMV | gmv | 原子 | 已支付订单金额合计 | `SUM(pay_amount) WHERE status=2` | `pay_time` | 不含取消/退款订单（status≠2） | `dwd_order_detail` | 数据组 |
| 订单量 | order_cnt | 原子 | 已支付订单笔数 | `COUNT(DISTINCT order_id) WHERE status=2` | `pay_time` | 不含取消/退款；按订单去重（一单多明细只算 1） | `dwd_order_detail` | 数据组 |
| 客单价 | atv | 复合 | 每笔已支付订单的平均金额 | `GMV ÷ 订单量` | 同统计周期 | 分母为 0 时返回 NULL，不返回 0 | GMV、订单量指标结果 | 数据组 |
| 复购率 | repurchase_rate | 复合 | 统计周期内复购用户占比 | `购买≥2次用户数 ÷ 统计周期购买用户数` | `pay_time`（周期内） | 分母为 0 时返回 NULL | 用户粒度指标结果 | 数据组 |
| 近7天GMV | gmv_7d | 派生 | 最近 7 天已支付金额合计（滚动窗口） | `SUM(pay_amount) WHERE status=2 AND pay_time >= NOW()-INTERVAL 7 DAY AND pay_time < NOW()` | `pay_time`（滚动窗口，基准=当前时间） | 不含取消/退款；窗口左闭右开 | `dwd_order_detail` | 数据组 |
| 新客GMV | new_user_gmv | 派生 | 新客产生的已支付金额合计 | `SUM(pay_amount) WHERE status=2 AND is_new_user=1` | `pay_time` | 新客判定：首次购买用户（`dim_user.is_new_user=1`），非"注册时间"口径 | `dwd_order_detail + dim_user` | 数据组 |

## 二、指标层级关系

```
原子：GMV、订单量、购买用户数（业务过程+度量，口径全仓唯一）
  └─ 派生：近7天GMV（+时间限定/滚动窗口）、新客GMV（+用户类型修饰）
       └─ 复合：客单价（GMV÷订单量）、复购率（复购用户数÷购买用户数）、支付转化率
```

## 三、口径变更标准流程

1. **变更前**：用血缘做影响分析（查下游报表/API/指标），评估影响面
2. **变更中**：双写/灰度，新旧口径并行跑一段做对比
3. **变更后**：更新字典版本（v1.0→v1.1，记录变更原因/生效时间）+ 通知下游 + 对账验证

## 四、指标平台四层映射（本字典的落点）

| 层 | 本项目的落点 |
|---|---|
| 定义层 | 本指标字典（唯一权威源） |
| 计算层 | 离线：Hive/Spark 算 DWS/ADS；实时：Flink SQL（读同一份口径） |
| 存储层 | ADS 指标表（T+1）+ Redis/ClickHouse（实时） |
| 服务层 | Day91 的 `/v1/ads/gmv` API + BI 接入 + 权限/缓存 |

## 五、关键设计约束

- 原子指标口径**全仓唯一**，派生/复合只能引用，不能另起定义
- 复合指标基于**指标结果**计算，不直接扫明细（保证口径一致）
- 派生指标的时间/维度限定必须**可落地为 SQL**（"新客"不定义清楚就是废话）
- 字典与元数据平台打通：指标 → 来源表 → 血缘（Day90）
