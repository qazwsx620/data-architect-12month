## 1. sed：按行处理文本（删 / 打印 / 替换）

### 1.1 删除行：数字寻址
```bash
sed '2d' test.log        # 删除第 2 行
sed '1,3d' test.log      # 删除第 1~3 行（逗号是范围分隔符）
sed -i '2d' test.log     # 直接修改原文件（-i）
```
> ⚠️ 易错点：
> - 删除第 1 行写 `1d`，**不是** `/1/d`（后者是"匹配包含字符1的行"，效果完全不同）
> - 行范围用逗号 `1,3d`，**不是** `1 - 3d`
> - 不带 `-i` 只是预览效果，原文件不变；`-i` 才真正落盘修改

### 1.2 删除行：内容匹配
```bash
sed '/warn/d' test.log   # 删除包含 warn 字符串的行
sed -i '/warn/d' test.log # 实战：清理垃圾日志直接改原文件
```

### 1.3 打印行：-n 静默模式
```bash
sed -n '2,4p' test.log   # 只输出第 2~4 行
```
> `-n`：关闭 sed 默认的"全部行输出"，只打印被 `p` 动作选中的行。
> 不加 `-n` 直接写 `sed '2,4p'` 会输出全部文本且 2~4 行重复打印一遍。

### 1.4 替换：s 命令
```bash
sed 's/旧/新/' file      # 每行替换第一个匹配
sed 's/旧/新/g' file     # g：一行内全部替换
sed 's/ERROR/ERR/g' file # 实战：敏感词/格式统一
```
> `s` 是 substitute 替换，`g` 是 global 全局（行内所有匹配都替换）。

### sed 寻址方式对比（面试高频）
| 写法 | 含义 |
|------|------|
| `2d` | 按**行号**删除第 2 行 |
| `1,3d` | 按**行范围**删除 1~3 行 |
| `/warn/d` | 按**内容匹配**删除含 warn 的行 |
| `2,4p` | 按行范围打印（配 `-n`） |

## 2. awk：按列处理文本（字段 / 筛选 / 统计）

### 2.1 字段基础
```bash
awk '{print $1}' test.log   # 第 1 列
awk '{print $1,$2}' test.log # 第 1、2 列
awk '{print $0}' test.log   # 整行
awk '{print $NF}' test.log  # 最后一列
```
- 默认分隔符：**空白**（空格、Tab，多个连续空白视为一个）
- `NF`：当前行字段**总数量**；`$NF`：**最后一列**（两者别混）

### 2.2 内置变量 NR / FNR（面试必考）
- `NR`：全局行号，处理多个文件时**持续累加不重置**
- `FNR`：单文件内部行号，**打开新文件重置为 1**
```bash
awk '{print NR,FNR,$0}' test.log test.log
# 读第二个文件时 NR 继续涨，FNR 重新从 1 开始
```

### 2.3 指定分隔符 -F
```bash
awk -F ':' '{print $1,$2}' test.log     # 冒号分隔
awk -F '[ :]' '{print $1,$2}' test.log  # 多分隔符：空格 或 冒号都切
```
> `[ :]` 是正则字符集合，匹配其中**任意一个字符**即做字段分割。
> 实战价值：日志 `2026-09-16 ERROR:connect failed`，一个 `-F '[ :]'` 直接拆出日期和级别，不用两次切割。

### 2.4 条件筛选
```bash
awk -F '[ :]' '$2=="ERROR" {print $0}' test.log   # 字符串匹配
awk '$3>100 {print $0}' data.txt                  # 数值比较
```
> ⚠️ 易错点：
> - 字符串比较用 `==`（比较），单个 `=` 是**赋值**，写混逻辑全错
> - 字符串大小写敏感：`ERROR` ≠ `error`

### 2.5 BEGIN / END 块（面试必考）
- `BEGIN{}`：**读取任何文件之前**执行一次 → 初始化变量、打印表头
- `END{}`：**读完所有行之后**执行一次 → 汇总统计
```bash
awk -F '[ :]' '
BEGIN{count=0}
$2=="ERROR"{count++}
END{print "ERROR日志总行数：",count}
' test.log
```

## 3. 综合实战：clean_log.sh（日志清洗）

需求：筛选 ERROR 和 warn → sed 替换（ERROR→ERR、warn→WARN）→ 统计清洗后记录数。

```bash
#!/bin/bash
set -euo pipefail
file_log="test.log"

echo "筛选和替换之后的结果"
awk -F '[ :]' '$2=="ERROR" || $2=="warn" {print $0}' $file_log | sed 's/ERROR/ERR/g;s/warn/WARN/g'

echo "清洗后的记录数"
awk -F '[ :]' '$2=="ERROR" || $2=="warn" {print $0}' $file_log | sed 's/ERROR/ERR/g;s/warn/WARN/g' | awk 'END{print NR}'
```
执行结果：
```
筛选和替换之后的结果
2026-09-16 ERR:connect failed
2026-09-16 WARN:timeout
2026-09-16 ERR:connect failed
清洗后的记录数
3
```

## 4. 大文件处理：流式 vs 全量加载（面试思考题）

sed / awk 都是**流式处理**：逐行读取 → 处理 → 输出，处理完一行释放一行内存。
几十 GB 的日志文件也只需要很小的常驻内存；一次性把文件全加载进内存的方案在大文件下会 OOM 崩溃。
> 数据开发里清洗超大日志、ETL 预处理都用这个特性，是选型的重要理由。

## 今日面试考点清单
1. awk 中 `$0` 代表？→ 完整一整行
2. awk `NF` 含义？→ 当前行字段总数量（`$NF` 才是最后一列）
3. awk `NR` 含义？→ 全局行号，多文件处理持续累加
4. `NR` 与 `FNR` 区别？→ FNR 是单文件行号，打开新文件重置为 1
5. awk `-F` 作用？→ 指定字段分隔符；`-F '[ :]'` 空格或冒号都分割
6. sed '3d' / '1,3d' / '/keyword/d' 含义？→ 删第3行 / 删1~3行 / 删含keyword的行
7. sed `-n` 作用？→ 静默模式，只输出 p 选中的行
8. sed `s/旧/新/g` 中 g 作用？→ 一行内全部替换
9. awk BEGIN{} 执行时机？→ 读取文件之前，执行一次
10. sed/awk 处理超大日志的优势？→ 流式逐行处理，内存占用小，不 OOM

## 踩坑记录（面试素材）
- awk 动作漏加单引号 `awk {print $1}` → bash 把 `$1` 当位置参数，`set -u` 下直接报"未绑定变量"；awk 程序体必须用单引号包裹
- 字符串比较写成 `=` → 变成赋值，条件永远成立；必须用 `==`
- 删除第 1 行写成 `/1/d` → 删掉所有含"1"的行；数字寻址直接写行号 `1d`
- 行范围写 `1 - 3d` → 语法错误；正确写法 `1,3d`
