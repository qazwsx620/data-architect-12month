## 1. 查看进程

### 1.1 ps / ps aux
```bash
ps aux        # 查看服务器全部进程
```
关键列：
- `USER`：进程所属用户
- `PID`：进程编号（操作系统给每个进程分配的唯一数字ID）
- `PPID`：父进程ID（创建这个进程的进程编号，终端里 bash 起的子进程 PPID 就是 bash 的 PID）
- `%CPU` / `%MEM`：CPU、内存占用
- `COMMAND`：执行的命令

### 1.2 grep 过滤进程 + 排除自身（面试高频坑）
```bash
ps aux | grep bash                  # 会带出 grep bash 自身那一行
ps aux | grep [b]ash                # 方法1：正则，grep 命令行里没有 "bash" 文本，匹配不到自己
ps aux | grep bash | grep -v grep   # 方法2：-v 反向过滤，排除含 grep 的行
```

### 1.3 top（实时监控）
```bash
top
```
交互快捷键：`q` 退出、`P` 按CPU排序、`M` 按内存排序、`1` 展开多核CPU视图。

### 1.4 pgrep（直接拿 PID）
```bash
pgrep bash         # 按程序名找 PID
pgrep -f loop.sh   # -f：匹配完整命令行字符串（适合脚本类进程，普通匹配只认程序名）
```
> 核心用途：拿到 PID 后配 kill 使用。

## 2. 信号与 kill（面试必考）

Linux 用**信号**和进程通信，kill 的本质是发信号：

| 信号 | 写法 | 行为 | 风险 |
|------|------|------|------|
| SIGTERM(15) | `kill PID`（默认） | 优雅终止：通知进程自行收尾（关文件、提交事务、释放连接）后退出；进程可忽略 | 低 |
| SIGKILL(9) | `kill -9 PID` | 内核直接销毁进程，无法捕获、无法忽略 | 高，可能丢数据/文件损坏 |
| SIGINT(2) | `Ctrl+C` | 终止前台进程 | - |
| SIGTSTP | `Ctrl+Z` | **暂停**进程挂起到后台，不退出，可用 bg 恢复 | - |
| SIGHUP | 终端关闭触发 | 挂断信号，普通后台任务会因此被杀 | - |

**kill -9 使用规范**：先 `kill PID` 优雅终止 → 等待 → 进程还在 → 才 `kill -9 PID`。直接 -9 是坏习惯，面试题常考。

## 3. 后台任务

### 3.1 & 后台运行 + jobs
```bash
sleep 30 &      # 命令末尾加 &，放后台，终端可继续输入
jobs            # 查看后台任务列表（[1] 任务编号 / 状态 / 命令）
```
- `fg 任务号`：后台任务切回**前台**运行
- `bg 任务号`：把**暂停(Stopped)**的任务恢复为后台运行
- `Ctrl+Z`：暂停当前前台任务，放后台（Stopped 状态）

> 记忆：Ctrl+C = 终止（kill），Ctrl+Z = 暂停挂起（不退出）。

### 3.2 nohup：关闭终端也不死（实战必备）
```bash
nohup /绝对路径/clean_log.sh > run.log 2>&1 &
```
- `nohup`：忽略 SIGHUP 挂断信号，关终端/断开 ssh 进程继续跑
- `> run.log`：标准输出(1)写入 run.log
- `2>&1`：标准错误(2)重定向到标准输出(1)的目标，即**错误也进 run.log**
- 末尾 `&`：后台执行

> ⚠️ 顺序坑：必须 `> run.log 2>&1`，写成 `2>&1 > run.log` 无效。
> ⚠️ 后台/nohup 场景脚本一律用**绝对路径**，相对路径易找不到文件。

### 3.3 停掉后台常驻进程的标准流程
```bash
pgrep -f loop_demo.sh   # 1. 拿 PID
kill PID                # 2. 优雅终止（SIGTERM）
pgrep -f loop_demo.sh   # 3. 复查还在不在
kill -9 PID             # 4. 仍在则强制终止
```

## 4. crontab 定时任务（ETL/日志采集高频）

### 4.1 语法
```
分 时 日 月 周  命令
```
| 字段 | 取值范围 |
|------|---------|
| 分钟 | 0-59 |
| 小时 | 0-23 |
| 日期 | 1-31 |
| 月份 | 1-12 |
| 星期 | 0-6（0=周日） |

特殊符号：`*` 每；`*/n` 每隔 n；`,` 多个；`-` 范围。

### 4.2 常用表达式（面试题）
| 表达式 | 含义 |
|--------|------|
| `* * * * *` | 每分钟 |
| `*/10 * * * *` | 每 10 分钟 |
| `0 3 * * *` | 每天凌晨 3 点 |
| `30 2 * * 1-5` | 周一到周五每天 02:30 |
| `0 8 * * 1` | 每周一 08:00 |
| `0 23 * * 0` | 每周日 23:00 |

### 4.3 常用命令
```bash
crontab -e    # 编辑当前用户定时任务
crontab -l    # 查看已有任务
crontab -r    # 删除全部任务（慎用！）
```

### 4.4 踩坑点（面试常问）
1. **环境变量**：crontab 执行环境与交互式终端不同，脚本内命令尽量写绝对路径，脚本开头可 source 环境变量
2. **日志**：crontab 输出不打印到终端，建议重定向留痕：
   ```
   0 8 * * 1 /home/vboxuser/test_demo/logs/clean_log.sh >> cron_run.log 2>&1
   ```
3. **星期与日期是「或」关系**：`0 0 1 * 0` = 每月1号 **或** 每周日零点执行，不是"1号且是周日"

## 今日面试考点清单
1. PID 是什么？→ Process ID，操作系统给每个进程分配的唯一编号
2. ps aux | grep bash 会带出自身进程，两种规避？→ `[b]ash` 正则 / `grep -v grep`
3. `-v` 参数作用？→ 反向匹配，排除含关键词的行
4. kill 与 kill -9 区别？→ SIGTERM 优雅终止可收尾 / SIGKILL 内核强杀不可捕获，仅优雅无效时用
5. Ctrl+C 与 Ctrl+Z 区别？→ SIGINT 终止 / SIGTSTP 暂停挂起
6. `2>&1` 含义？→ 标准错误重定向到标准输出目标，一起写日志
7. nohup 作用？→ 忽略 SIGHUP 挂断信号，关终端进程继续跑
8. pgrep -f 作用？→ 按完整命令行匹配查找进程
9. crontab 里脚本为什么要绝对路径？→ crontab 工作目录/环境与终端不同，相对路径找不到

## 踩坑记录（面试素材）
- `ps aux | grep bash` 带出 grep 自身 → `[b]ash` 或 `grep -v grep`
- 顺序写反 `2>&1 > run.log` → 错误输出没进日志；正确顺序 `> run.log 2>&1`
- crontab 写相对路径 → 到点不执行，日志查不到；必须绝对路径
- 直接 kill -9 正在写数据的进程 → 文件损坏/数据丢失；先 SIGTERM 再 -9
- 关终端后后台 `&` 任务消失 → 用 nohup 才不受挂断影响
