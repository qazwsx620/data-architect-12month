## 1. inode 与文件系统

### 1.1 inode 是什么
磁盘格式化后，分区被划分为两部分：
- **inode 区**：存放文件的**元数据**（大小、属主、属组、权限、时间戳、数据块指针）
- **数据区**：存放文件的**实际内容**

> ✅【面试高频】inode **不存储文件名**！文件名存放在**目录的条目**里，目录维护「文件名 → inode」的映射关系。

### 1.2 查看 inode
```bash
ls -li 文件      # -i：显示 inode 编号
stat 文件        # 查看 inode 详细信息（含链接计数、各时间戳）
```
> ⚠️【易混淆坑】`stat` 里的链接计数 = 该 inode 的文件名条目数（含硬链接），不是软链接数量。

### 1.3 inode 耗尽（实战坑）
```bash
df -i      # 查看 inode 使用率
```
小文件极多的场景：**磁盘没满，但 inode 用尽**，无法创建新文件。清理方式：删除大量无用小文件，而不是删大文件。

## 2. 硬链接与软链接（面试必考）

### 2.1 硬链接 `ln`
- 本质：同一个 inode **新增一个文件名别名**，inode 链接计数 +1
- 限制：**不能跨分区**、**不能链接目录**
- 删除源文件：只是删掉一个目录条目，计数未归零，**硬链接依旧可正常访问**

### 2.2 软链接 `ln -s`
- 本质：**独立的新文件（新 inode）**，内容存的是**源文件路径字符串**
- 特点：**可以跨分区**、**可以链接目录**
- 源文件删除：变成**悬空链接（broken link）**，cat 报"没有那个文件或目录"；**新建同名文件后自动恢复指向**

### 2.3 软硬链接对比（背熟）
| 特性 | 硬链接 `ln` | 软链接 `ln -s` |
|------|------------|----------------|
| inode | 与源文件相同 | 独立 inode |
| 本质 | 同一 inode 的别名 | 存路径字符串的独立文件 |
| 跨分区 | ❌ 不支持 | ✅ 支持 |
| 链接目录 | ❌ 不允许 | ✅ 允许 |
| 删除源文件后 | 不受影响，依旧可用 | 悬空；新建同名文件可恢复 |
| 占用空间 | 几乎不占 | 存储路径字符串 |

## 3. 文件权限 rwx

### 3.1 三组权限
`-rwxr-xr-- 1 vboxuser vboxuser 152 9月17 19:41 test.log`
- 第1位：文件类型（`-`普通文件 / `d`目录 / `l`软链接）
- 第2~4位 `u` 属主、第5~7位 `g` 属组、第8~10位 `o` 其他用户

### 3.2 rwx 文件 vs 目录（高频坑）
| 权限 | 文件 | 目录 |
|------|------|------|
| r (4) | 读取内容 | 列出目录内文件名 |
| w (2) | 修改内容 | 增、删、重命名目录内文件 |
| x (1) | 执行程序 | **cd 进入目录**，访问文件元数据 |

> ⚠️【易混淆坑】目录无 x 权限：即使有 r，也无法进入目录、无法查看文件详情。
> ⚠️【易混淆坑】目录有 w 权限 ≠ 能改目录内文件的内容！文件内容修改看**文件自身权限**。

### 3.3 数字权限算法
r=4、w=2、x=1，相加：
`rwxr-xr--` → u:7 g:5 o:4 → **754**

### 3.4 修改权限与归属
```bash
chmod 755 文件          # 数字方式
chmod u+x 文件          # 符号方式：u/g/o/a + +/- rwx
chown 属主:属组 文件     # 修改属主与属组
```

## 4. umask（新建文件默认权限）

> ✅【面试高频】umask 控制**新建文件/目录的默认权限**。
> ⚠️【易混淆坑】是**按位掩码屏蔽**，不是简单算术减法（日常可近似相减估算）。

系统初始最大权限：
- 文件：**666**（默认不带执行 x，出于安全）
- 目录：**777**（目录必须带 x 才能进入）

```
umask=022 → 新文件 666-022=644，新目录 777-022=755
umask=002 → 新文件 664，新目录 775
```
```bash
umask          # 查看当前掩码
```

## 5. 特殊权限 SUID / SGID / Sticky（面试必考）

### 5.1 SUID（Set User ID）—— 仅二进制可执行文件
- 程序运行时，**临时使用文件属主身份**执行，不是调用者身份
- 典型案例：`passwd`——普通用户改密码，靠 SUID 拿到 root 身份写 `/etc/shadow`
- 标记：属主 x 位变 `s`；**shell 脚本设置 SUID 不生效**（Linux 安全限制）

### 5.2 SGID（Set Group ID）
- 文件：运行进程临时使用**文件属组**身份
- 目录：目录内新建文件**自动继承目录属组**（团队共享目录）
- 标记：属组 x 位变 `s`

### 5.3 Sticky Bit 粘滞位 —— 仅目录
- 目录内文件**仅文件所有者可删除/改名**，别人即使目录有 w 权限也删不了
- 典型例子：`/tmp`
- 标记：其他用户 x 位变 `t`
> ⚠️【易混淆坑】粘滞位不限制**修改文件内容**，只限制删除/重命名。

### 5.4 大小写 s/t 含义
- 小写 `s` / `t`：特殊权限开启，且该位原本有 x 权限（有效）
- 大写 `S` / `T`：特殊权限开启，但原本**没有 x 权限**（无效状态）

## 6. 磁盘挂载 mount / umount

### 6.1 基本概念
- Linux **一切皆文件**，分区必须**挂载到目录（挂载点）**才能访问
- mount 输出格式：`设备 on 挂载点 type 文件系统类型 (挂载选项)`
```bash
mount                 # 查看已挂载设备
df -h                 # 查看磁盘使用
lsblk                 # 查看磁盘分区结构
```

### 6.2 umount 卸载（⚠️拼写：是 umount 不是 unmount）
```bash
sudo umount /挂载点
```
> ⚠️【易混淆坑】报 `target busy` 常见原因：
> 1. 当前 shell 工作目录就在挂载点内部（最常见）
> 2. 有进程打开挂载点内文件，持有句柄
> 3. 管道/重定向占用挂载点内文件句柄
> 排查：`lsof +D 挂载点` 或 `fuser -m 挂载点`，kill 占用进程后再卸载。

### 6.3 /etc/fstab（开机自动挂载）
```
设备名(UUID推荐)  挂载点  文件系统类型  挂载选项  dump  自检
/dev/sda3         /       ext4         defaults  0     1
```
- 推荐写 **UUID**，磁盘顺序变化不影响
- 挂载点必须是已存在的空目录

### 6.4 loop 挂载实验（镜像文件模拟磁盘）
```bash
dd if=/dev/zero of=test.img bs=1M count=10   # 创建 10M 空白镜像
mkfs.ext4 test.img                            # 格式化为 ext4
mkdir /tmp/mnt_test
sudo mount test.img /tmp/mnt_test             # 普通用户 mount 需要 sudo
```
> ⚠️【易混淆坑】镜像已挂载后删除 test.img：**挂载点内读写照常**（loop 进程持有文件句柄，数据未释放），直到 umount 后文件才真正消失。

## 今日面试考点清单
1. inode 里是否存储文件名？→ 不存，inode 存元数据；文件名存目录条目
2. 硬链接能否跨分区？删除源文件后硬链接？→ 不能跨分区；删除源文件后依旧可访问
3. 目录有 w 权限能改目录内文件内容吗？→ 不能；目录 w 只管增/删/重命名，内容修改看文件自身权限
4. umask=022，新文件和新目录默认权限？→ 文件 644，目录 755
5. SUID 作用在什么文件？执行时身份如何变化？→ 二进制可执行文件；以文件属主身份运行
6. 粘滞位作用对象？限制是什么？→ 仅目录；目录内文件只能文件所有者删除
7. umount target busy 常见原因？→ 当前目录在挂载点内 / 进程打开挂载点内文件 / 管道重定向占用句柄

## 踩坑记录（面试素材）
- 误以为 inode 存文件名 → inode 只有元数据，文件名在目录条目
- 软链接删除源文件后悬空，误以为文件损坏 → 新建同名文件即可恢复（软链接只认路径）
- 目录无 x 权限：有 r 也进不去目录 → 目录访问三权：r 列表、w 增删、x 进入
- 目录 w 权限被误认为能改文件内容 → 内容权限在文件自身
- umask 被当成算术减法 → 实际是按位掩码屏蔽
- SUID 给 shell 脚本设置无效 → 仅二进制可执行文件生效
- 粘滞位被误认为限制修改内容 → 只限删除/重命名，修改内容不受限
- umount 拼写成 unmount → 正确是 umount
- 挂载点内 cd 着就 umount → target busy；先退出目录再卸载
- 镜像挂载后删 img 文件以为数据丢失 → 句柄未释放，umount 前读写照常
