## 1. 数据质量为什么重要（面试必答）

数仓数据不准 → 报表错 → 业务决策错 → 数据团队失信。**质量是数仓的生命线**。

## 2. 4 类校验规则（面试高频）

| 规则 | 检测什么 | 阈值例子 |
|------|----------|----------|
| 空值率 | 关键字段空值比例 | 金额空值率 < 1% |
| 主键唯一 | 主键重复 | 唯一性 = 100% |
| 行数波动 | 今天 vs 昨天行数偏差 | 波动 < ±20% |
| 金额异常 | 负金额/超上限 | 0 < 金额 < 10万 |

> 规则 = 业务定义阈值 + 数据团队实现；每层跑完 ETL 立即校验。

## 3. 校验脚本实现（quality_check.py 核心）

```python
def check(conn, name, sql):
    cursor.execute(sql)
    bad_count = cursor.fetchone()[0]
    ok = bad_count == 0
    print(f"[{'PASS' if ok else 'FAIL'}] {name}: 异常数={bad_count}")
    return ok

# 校验项：
# ODS-订单主键唯一 / DWD-金额非负 / DWD-金额空值
# DWS-用户汇总金额非负 / ADS-GMV非负

# 告警：任一失败 → exit 1（调度系统据此判定任务失败）
sys.exit(run_checks())   # 0=通过 1=失败
```

## 4. 告警机制

| 机制 | 作用 |
|------|------|
| 终端打印 [PASS]/[FAIL] | 人工查看 |
| exit code（0/1） | 调度系统判定失败 → 触发重试/告警 |
| 日志 | 留痕可追溯 |

## 5. 数据血缘（面试重点）

**血缘 = 数据从哪来、到哪去、经过哪些加工**：
```
biz_user/biz_product/biz_order
    ↓ 全量/增量抽取
ods_order
    ↓ 清洗
dwd_order_detail
    ↓ 汇总
dws_user_daily + dws_product_daily
    ↓ 报表
ads_gmv_report
    ↓ 最终去向
CSV/HTML
```
血缘三用：**① 出问题快速定位 ② 评估影响面 ③ 审计追溯**。
排查方法：**自下向上逐层反查**（业务库→ODS→DWD→DWS→ADS）。

## 今日面试考点清单
1. 4类校验规则？→ 空值率/主键唯一/行数波动/金额异常
2. 怎么告警？→ 打印+exit code 供调度判定
3. 血缘有什么用？→ 快速定位/影响面/审计
4. 为什么逐层校验？→ 上游错误不传导下游
5. 怎么排查？→ 自下向上逐层反查

## 踩坑记录（面试素材）
- 校验放最后统一查 → 上游脏数据已污染下游，返工大
- 只打印不 exit → 调度系统不知道失败，不会重试
- 无血缘 → 出问题大海捞针
- 规则没阈值 → 没法判定"多少算异常"
