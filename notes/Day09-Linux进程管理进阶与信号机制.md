## 1. 进程状态（面试必考）

`ps` 输出 STAT 列的字母代表进程状态：

| 状态 | 含义 | 关键点 |
|------|------|--------|
| R | 运行态 | 正在 CPU 执行或等待调度 |
| S | 可中断睡眠 | 等待事件（IO/信号），**可被信号唤醒** |
| D | 不可中断睡眠 | 等待磁盘 IO，**无法被信号杀死** |
| Z | 僵尸进程 | 子进程退出，父进程未回收 |
| T | 停止状态 | 被暂停（Ctrl+Z / SIGSTOP） |
| I | Idle | 内核空闲线程专用 |

STAT 附加字母：
- `s`：会话领导者（session leader，终端首进程）
- `+`：前台进程组
- `<`：高优先级（nice 为负）
- `N`：低优先级

> ⚠️【易混淆坑】D 状态进程连 `kill -9` 都杀不掉，只能等 IO 完成或重启。
> 内核线程（`[kworker]` 等）VSZ/RSS 为 0，不占用户空间内存。

## 2. 僵尸进程（高频面试）

**产生原理**：子进程先退出，内核保留其 PCB（保存退出状态），等父进程 `wait()/waitpid()` 回收；**父进程存活但不调用 wait → 子进程残留为 Z**。

**特点**：
- 不占用 CPU、内存（代码/资源已释放）
- **占用 PID 号**：大量僵尸堆积会耗尽系统 PID，无法创建新进程

**清理方案**：
1. 杀掉父进程 → 僵尸变孤儿，被 systemd(PID=1) 收养自动回收
2. 修复父进程代码，增加 wait/waitpid 及时回收
3. 极端情况重启系统

> ⚠️【易混淆坑】`kill -9 僵尸PID` 无效：僵尸进程已经死亡，无法接收任何信号；只能处理其父进程。

**孤儿进程**：父进程先退出、子进程还在运行 → 子进程被 systemd 收养并自动回收，**无危害**。

## 3. Linux 信号机制 signal

信号是内核发给进程的**异步通知**。进程收到信号有三种处理方式：默认动作 / 忽略 / 捕获（执行自定义函数）。

```bash
kill -l      # 查看全部信号（1-31 标准信号，34-64 实时信号）
```

高频信号表（背熟）：
| 信号 | 编号 | 触发 | 行为 |
|------|------|------|------|
| SIGHUP | 1 | 终端关闭/挂断 | 挂断；常用于让进程重读配置 |
| SIGINT | 2 | Ctrl+C | 中断进程 |
| SIGKILL | 9 | kill -9 | **强制杀死，不可捕获/忽略** |
| SIGTERM | 15 | kill（默认）| 优雅终止，可捕获做清理 |
| SIGCHLD | 17 | 子进程退出 | 通知父进程回收（不处理→僵尸） |
| SIGCONT | 18 | bg/fg | 恢复暂停进程 |
| SIGSTOP | 19 | kill -19 | **强制暂停，不可捕获/忽略** |
| SIGTSTP | 20 | Ctrl+Z | 暂停，**可捕获** |

> ⚠️【易混淆坑】**Ctrl+Z 发送的是 SIGTSTP(20)（可捕获），不是 SIGSTOP(19)（不可捕获）**；SIGSTOP 没有键盘快捷键，只能用 kill -19 发送。
> ✅【面试高频】`kill PID` 默认 SIGTERM 可被捕获/忽略，进程卡死无响应时 SIGTERM 无效 → 才用 `kill -9`；生产规范：先 TERM 等待，失败再 KILL，不要上来就 -9。

## 4. 杀进程工具

```bash
kill PID            # 默认 SIGTERM(15) 优雅终止
kill -9 PID         # SIGKILL 强杀，最后手段
killall 进程名       # 按名称杀全部同名进程
pkill -f 关键字      # 按完整命令行匹配杀
```

## 5. nice 优先级（CFS 调度器）

- nice 范围：**-20 ~ 19**，值**越小权重越高**，分到更多 CPU 时间片
- 默认新建进程 nice = 0
- 普通用户：只能把 nice 调大（降低优先级）
- root：可以设置负数（最高 -20）

```bash
ps -o pid,ni,cmd          # 查看 nice 值（NI 列）
nice -n 5 sleep 300 &     # 启动时指定 nice
renice 10 -p PID          # 修改运行中进程 nice
```

> ⚠️【易混淆坑】Linux 默认 CFS 调度器下，nice 只影响权重（CPU 时间片占比），**不是传统硬抢占优先级**；nice=-20 也不能无条件抢占正在运行的进程。

## 今日面试考点清单
1. 僵尸进程 STAT 是什么？能否 kill -9 杀死？→ Z；不能，进程已死，只能处理父进程
2. 僵尸进程占用什么资源？→ 不占 CPU/内存，占 PID 号，大量堆积耗尽 PID
3. 僵尸进程怎么清理？→ 杀父进程（孤儿被 systemd 收养）或修复代码加 wait()
4. Ctrl+Z 产生什么信号？SIGSTOP 能捕获吗？→ SIGTSTP(20) 可捕获；SIGSTOP(19) 不可捕获
5. 为什么 kill 有时杀不掉进程？→ SIGTERM 可被捕获/忽略，进程卡死无响应；用 SIGKILL
6. D 状态进程为什么杀不死？→ 不可中断睡眠，等磁盘 IO，只能等完成或重启
7. nice 范围？普通用户能设负数吗？→ -20~19；不能，仅 root
8. 孤儿进程有危害吗？→ 无，被 systemd 收养自动回收

## 踩坑记录（面试素材）
- 误以为 Ctrl+Z 是 SIGSTOP → 实际是 SIGTSTP(20)，可捕获；SIGSTOP(19) 无快捷键
- kill -9 僵尸进程 → 无效，僵尸已死；处理父进程
- 父进程提前退出看不到僵尸 → 制造僵尸必须子先退、父存活且不 wait
- nice 当成硬抢占优先级 → CFS 下只影响权重，不是绝对抢占
- 内核线程 VSZ/RSS=0 误以为异常 → 内核线程不占用户空间内存，正常
