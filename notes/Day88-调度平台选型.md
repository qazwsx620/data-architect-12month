# Day88 总结笔记：调度平台选型

> 日期：2026-11-04 ｜ 模块七：数据平台工程 ｜ 状态：✅ 理论 + 选型对比表

## 一、四大调度平台定位

| 平台 | 一句话定位 | 核心抽象 |
|---|---|---|
| Airflow | DAG 即代码，数据工程事实标准 | DAG / Operator / Task（已实操）|
| DolphinScheduler | 可视化 DAG 拖拽，工作流调度 | 工作流 + 任务节点 |
| xxl-job | 轻量分布式**定时任务中心** | 任务 + cron + 分片广播 |
| DataWorks | 云原生数仓一站式调度（阿里云托管） | 周期实例 + 依赖 + 补数据 |

## 二、选型对比表（scripts/day88/调度平台选型对比表.md）

| 维度 | Airflow | DolphinScheduler | xxl-job | DataWorks |
|---|---|---|---|---|
| 一句话定位 | DAG即代码，数据工程事实标准 | 可视化DAG拖拽，工作流调度 | 轻量分布式定时任务中心 | 云原生数仓一站式调度 |
| DAG 定义方式 | DAG即代码 | DAG可视化拖拽 | 表达不了 DAG 依赖 | 周期实例 + 依赖配置 |
| 技术栈/生态 | python/Apache | java/Apache | java单体 | 阿里云商业化（云服务）|
| 多租户/权限 | 弱（单租户为主） | 强（多租户） | 简单分组/执行器权限，偏弱 | 强（项目空间权限体系）|
| 适合场景 | python、任务复杂、代码版本化 | java、可视化门槛低、多租户 | 单点定时任务 | 公司接入阿里云，不想管基础设施 |

## 三、选型四步法（面试方法论）

1. **看依赖复杂度**：有 DAG 依赖 → Airflow/DS；纯定时单任务 → xxl-job
2. **看团队技术栈**：Python → Airflow；Java → DS / xxl-job
3. **看部署形态**：已在阿里云全家桶 → DataWorks；自建/混合云 → 开源
4. **看运维资源**：人少不想管基础设施 → 托管/轻量；有平台团队 → Airflow/DS

## 四、订单数仓场景结论

场景：四层 ETL（ODS→DWD→DWS→ADS）+ 报表导出 + 质量校验，Python + MySQL，未来接 Spark/Flink。
需求：依赖阻断、失败重试、补数、可视化监控、生态集成。
**结论：Airflow**（Python 栈 + 复杂依赖 + 代码版本化 + 生态；Day87 已实操跑通）。

## 五、面试答案模板

> "订单数仓调度用 Airflow。对比过 DolphinScheduler 和 xxl-job：ETL 是四层依赖链，要求上游失败下游阻断、重试、补数，这是 DAG 编排能力；团队 Python 栈；后续接 Spark/Flink。xxl-job 是定时任务中心表达不了依赖，DS 主打可视化但我们更需要代码版本化，所以选 Airflow。"

追问收法：
- DataWorks：公司自建/混合云，没上阿里云全家桶
- DolphinScheduler：适合 Java 团队 + 可视化低门槛，我们 Python 栈 + 代码版本化优先

## 六、今日小测试要点

- xxl-job ≠ DAG 编排平台（"到点跑" vs "按依赖跑"）
- Airflow vs DS 核心分歧：代码优先 vs 配置（可视化）优先
- DataWorks 心智：任务 = 调度配置，实例 = 实际跑的东西（一个日调度任务每天一个实例）
- 面试答案链：场景 → 需求拆解 → 对比排除 → 结论
