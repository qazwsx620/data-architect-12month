# Day93 总结笔记：数仓规范

> 日期：2026-11-07 ｜ 模块七：数据平台工程 ｜ 状态：✅ 理论 + 《数仓开发规范》文档入库

## 一、命名规范

### 表命名 = 分层前缀 + 业务域 + 主题 + 周期/粒度

| 层 | 规范 | 示例 |
|---|---|---|
| ODS | `ods_{业务域}_{表名}` | `ods_order` |
| DWD | `dwd_{业务域}_{主题}_{粒度}` | `dwd_order_detail` |
| DWS | `dws_{业务域}_{维度}_{周期}` | `dws_user_daily` |
| ADS | `ads_{报表/主题}_{周期}` | `ads_gmv_report` |
| 实时 | `rt_` 前缀 / `_rt` 后缀 | `rt_gmv_1min` |
| 临时/中间 | `tmp_` / `mid_` | `tmp_order_clean` |
| Kafka topic | `{业务域}_{层}_{主题}` | `ods_order` |

### 字段命名
`is_xxx`（布尔）、`xxx_time`（时间）、`xxx_amount`（金额）、`xxx_cnt`（数量）、`xxx_id`（标识）；全小写下划线，禁中文/拼音/驼峰。

### 分区命名
日期统一 `dt=yyyy-MM-dd`，小时统一 `hour=HH`；**全仓禁止混用 p_date/date_str/day**——混用会导致调度、补数、血缘、生命周期管理全部要特判。

### 任务命名
`{环境}_{分层}_{表名}`，全局唯一；Flink 作业同名规则，便于 WebUI 定位。

## 二、分层规范

| 层 | 允许做 | 禁止做 |
|---|---|---|
| ODS | 贴源同步、格式统一 | 业务清洗、聚合、删字段 |
| DWD | 清洗、去重、口径统一、维度关联 | **重度聚合（必须保持明细粒度）** |
| DWS | 按主题/维度轻汇总、沉淀原子指标 | 最终报表格式、复杂计算 |
| ADS | 面向报表/大屏/API 最终汇总 | 回溯加工明细 |

**跨层引用红线**：
1. 禁跨层：ADS 不读 ODS/原始 topic，DWD 不绕过 ODS 直读业务库
2. 禁同层互读（DWS 表之间不互读）
3. ADS 只依赖 DWS/DWD，不依赖其他 ADS

**实时对应**：ODS=Kafka topic → DWD=Flink 清洗 → DWS=Flink 窗口聚合 → ADS=结果表（JDBC/Redis/CK）。

## 三、开发规范

### SQL
- 禁 `SELECT *`
- **分区裁剪**：`WHERE dt='2026-11-06'`；禁止 `date_format(dt,...)` 包住分区字段（分区失效、全表扫）
- JOIN 显式 ON、别名统一；大表 JOIN 小表优先广播；倾斜加盐
- 日期参数化 `${dt}`；复杂逻辑必须注释

### 离线任务
- 一任务一输出表；**必须幂等**（`INSERT OVERWRITE` / 分区覆盖）
- 重试/超时/告警/依赖配置齐全；禁读他人中间表

### Flink 任务（实时）
- 并行度：按 Source 分区数与吞吐反推；Sink 受连接池约束；**禁止默认 1**
- Checkpoint：核心链路 1min、一般 3~5min；最小间隔/超时按间隔取半；快照落 HDFS 保留 2~3 份；`EXACTLY_ONCE`
- 状态后端：小状态内存、大状态 RocksDB + 增量 checkpoint + 状态 TTL（防状态膨胀）

### 实时一致性
Kafka offset（随 checkpoint 快照）+ checkpoint 算子状态 + Kafka Sink 两阶段提交 = 端到端 Exactly-Once；**不支持事务的 MySQL Sink 用幂等 upsert 兜底**。

### 数据质量
主键唯一、关键字段非空、金额非负、行数波动阈值；上线前校验 + 告警；实时双链对账（前提口径统一）。

## 四、评审流程与落地

评审四道关：需求（口径/来源/粒度）→ 设计（分层/表结构/分区/血缘）→ 代码（SQL/幂等/性能）→ 上线（校验/回滚/通知）。

落地手段：模板（建表/SQL/任务/DAG）+ **CI 卡点**（命名/格式/禁 SELECT * 检查）+ 元数据登记 owner/血缘 + 定期巡检评审。只写文档不落流程 = 没落地。

## 五、面试答案

**数仓规范包含什么**：命名（表/字段/分区/任务）、分层（职责边界+跨层红线）、开发（SQL/任务/实时/质量）、评审流程、落地手段。
**怎么落地**：模板 + CI 卡点 + 元数据登记 + 巡检评审，进流程而不是挂文档。

## 六、今日小测试（5 题全过）

1. 各层前缀+实时命名 2. 分区不统一→调度/补数/血缘特判 3. DWD 保持明细、DWS 轻聚合 4. 函数包分区字段→裁剪失效 5. 幂等 INSERT OVERWRITE + Exactly-Once 三件套

## 七、易混淆坑

- DWD 必须明细粒度，不能顺手聚合
- DWS 是公共汇总（可复用），ADS 面向具体应用
- 分区字段被函数包住是性能杀手
- 幂等是任务红线，重跑翻倍即事故
- 规范不进评审/CI 就是废纸
