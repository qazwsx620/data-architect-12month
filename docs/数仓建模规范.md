# 数仓建模规范（v1.0）

> 覆盖：订单 / 用户 / 商品三大主题 ｜ 维护：数据组 ｜ 生效：2026-11-07
> 配套：《数仓开发规范》（命名/分层/SQL/评审，Day93）

## 一、建模原则

1. **星型模型优先**：事实表 + 维度表直接关联；雪花（维度再拆子维）仅在维度层级复杂且查询可接受时使用，不作为默认
2. **粒度最细优先**：事实表先建最细粒度，汇总在上层做；禁止在明细层顺手聚合
3. **一致性维度**：所有事实表引用同一套公共维表（DIM 层）
4. **分层归位**：明细事实归 DWD，轻汇总归 DWS，应用归 ADS（跨层引用按 Day93 红线）
5. **口径对齐指标字典**（Day92）：模型里的度量与指标定义一致

## 二、事实表规范

### 2.1 三种类型

| 类型 | 定义 | 示例 |
|---|---|---|
| 事务事实表 | 一行一个业务事件，最细粒度 | `dwd_order_detail`（一行=一个订单明细） |
| 周期快照事实表 | 按固定周期对状态做快照 | `dws_user_daily`（一行=一个用户一天）、`dws_product_daily`（一行=一个商品一天） |
| 累积快照事实表 | 一行一个流程实例，随流程推进更新 | 订单全流程表（下单→支付→发货→完成） |

### 2.2 规范要求

- **粒度必须明确且最细**：写清"一行代表什么"，避免一单多明细重复计数
- 主键：业务主键/代理键 + 维度外键，唯一非空
- 度量分类：可加（金额/数量）、半可加（余额）、**不可加（比率，不能直接 SUM）**
- 分区：`dt`（日）/`hour`（时），符合命名规范

## 三、维度表规范

- 命名 `dim_` 前缀；主键用**代理键**（与业务键解耦）或统一业务键
- 属性含描述属性 + 层级属性（品类/地区）
- **缓慢变化维（SCD）**：
  - Type1：直接覆盖，不保留历史
  - Type2：加版本行 + 生效/失效时间 = **拉链表**（可查历史状态）
  - Type3：加列存上一版值
- 每个维度必须明确 SCD 策略，写入元数据

## 四、一致性维度管理

1. **全仓唯一公共维表**（DIM 层），禁止各主题各建一份
2. **统一编码/主键/值域**（商品类目、地区编码全仓一套）
3. **变更评审 + SCD 策略统一**：维度属性变更走评审，明确是否保留历史
4. **元数据登记**：维度表、owner、口径、被哪些事实表引用
5. **同步机制**：每日全量快照 或 拉链增量，保证下游能拿到最新维度

常见问题：同名不同义、维度漂移（变更未同步下游）、维度缺失（兜底值/实时侧输出流）。

## 五、三大主题模型清单

### 5.1 订单主题

| 项 | 内容 |
|---|---|
| 核心事实表 | `dwd_order_detail` |
| 粒度 | 一个订单明细（一单多商品 = 多行） |
| 类型 | 事务事实表 |
| 关联维度 | `dim_user`(user_id)、`dim_product`(product_id)、`dim_date`(dt) |
| 汇总表 | `dws_user_daily`、`dws_product_daily` |
| 应用表 | `ads_gmv_report` |

### 5.2 用户主题

| 项 | 内容 |
|---|---|
| 核心事实表 | `dwd_order_detail`（复用订单明细，按 user_id 汇总） |
| 粒度 | 一个用户一天（一行） |
| 类型 | 周期快照事实表 |
| 关联维度 | `dim_user`(user_id)、`dim_date`(dt) |
| 汇总表 | `dws_user_daily` |
| 应用表 | `ads_user_report`（规划命名） |

### 5.3 商品主题

| 项 | 内容 |
|---|---|
| 核心事实表 | `dwd_order_detail`（复用订单明细，按 product_id 汇总） |
| 粒度 | 一个商品一天（一行） |
| 类型 | 周期快照事实表 |
| 关联维度 | `dim_product`(product_id)、`dim_date`(dt) |
| 汇总表 | `dws_product_daily` |
| 应用表 | `ads_product_report`（规划命名） |

> 说明：用户/商品主题当前复用订单明细事实；若后续引入行为日志（浏览/收藏），需单独建行为事实表并明确粒度。

## 六、模型评审清单

- [ ] 粒度明确且最细（一行代表什么写清楚）
- [ ] 主键唯一非空、维度外键完整
- [ ] 分层归位正确，无跨层引用/同层互读
- [ ] 引用公共维表（一致性维度）
- [ ] 度量可加性标注（比率不可加）
- [ ] 指标口径与指标字典一致
- [ ] 命名/分区符合《数仓开发规范》
- [ ] 有 owner、注释、质量规则

## 七、变更管理

- 模型变更（加字段/改粒度/换维表）走设计评审 + 血缘影响分析
- 粒度变更属**破坏性变更**，必须新旧并行 + 通知下游 + 对账
- 维表 SCD 策略变更需同步更新元数据与下游关联逻辑
